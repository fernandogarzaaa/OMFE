# Deploy

OFM Engine ships as one container image that runs either the web server (`serve`, default) or
the job worker (`worker`). It needs PostgreSQL in production; Redis is optional.

| Option | Good for | Cost |
|---|---|---|
| [Render Blueprint](#render-free-blueprint) | demos, pilots | $0 (with free-tier limits) |
| [Docker image on any host](#docker-image-ghcrio) | production on a VM, Fly, ECS, Kubernetes … | host-dependent |
| [Docker Compose](#docker-compose) | local evaluation, single VM | $0 locally |

Before any internet-facing deploy, read the **Go-live checklist** in the
[README](../README.md#go-live-checklist).

## Required production settings

Production boot (`ENV=production`) **refuses to start** if any of these is unsafe
(`settings.production_problems()`):

| Variable | Rule |
|---|---|
| `DATABASE_URL` | must be Postgres (SQLite is refused) |
| `JWT_SECRET` | not the dev default, 32+ characters |
| `MASTER_KEYS` | not the dev key; Fernet key(s) from `ofm gen-key`, comma-separated, newest first |
| `PII_HASH_SALT` | not the dev default; random; never change after go-live |
| `ARGON2_*` | not below OWASP minimums (m ≥ 19456 KiB, t ≥ 2) |
| `OUTBOUND_ALLOW_PRIVATE` | must be false |

Also set `PUBLIC_BASE_URL` (your https origin), `FORWARDED_ALLOW_IPS` (the proxy addresses
allowed to set `X-Forwarded-For/Proto`; `*` only behind a managed load balancer that overwrites
them), and `METRICS_TOKEN` if you scrape `/metrics`.

Generate secrets locally or with the image:

```bash
ofm gen-key                                             # MASTER_KEYS
python -c "import secrets;print(secrets.token_urlsafe(48))"   # JWT_SECRET, PII_HASH_SALT, METRICS_TOKEN
docker run --rm ghcr.io/fernandogarzaaa/omfe gen-key    # same, without a local install
```

### First admin without a shell

Platforms without shell access (such as Render free) can create the first tenant and admin at
boot: set `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD` and optionally `BOOTSTRAP_TENANT`
(slug, default `demo-agency`). The admin is created only if that email does not exist yet; remove
the password variable after the first login and change the password in the app. With a shell,
use `ofm init-client <slug> --admin-email …` instead.

Agency YAML files (`clients/<slug>.yaml`) are baked into the image at `/app/clients`, so commit
them before building, or set the editable parts (branding, funnel copy, integration ids) from the
UI/API overrides.

## Render (free Blueprint)

[`render.yaml`](../render.yaml) defines a Docker web service (`ofm-engine`, plan `free`,
branch `main`, health check `/healthz`) and a free Postgres (`ofm-db`).

1. Fork or push the repository to your GitHub account.
2. Render Dashboard → **New → Blueprint** → select the repository → Render reads `render.yaml`.
3. Fill the prompted variables:
   - `PUBLIC_BASE_URL` — e.g. `https://ofm-engine.onrender.com` (or your custom domain).
   - `MASTER_KEYS` — paste the output of `ofm gen-key`.
   - `JWT_SECRET`, `PII_HASH_SALT` and `METRICS_TOKEN` are generated by Render
     (`generateValue: true`).
4. Optionally add `BOOTSTRAP_ADMIN_EMAIL` / `BOOTSTRAP_ADMIN_PASSWORD` (above).
5. Deploy. The entrypoint runs `ofm migrate`, then serves on `$PORT`.

What the blueprint sets and why:

| Setting | Value | Reason |
|---|---|---|
| `RUN_WORKER_IN_PROCESS` | `true` | free web services cannot run a separate background worker, so the job worker runs on a thread inside the web process |
| `WEB_CONCURRENCY` | `1` | one process → one in-process worker and one in-memory rate limiter |
| `FORWARDED_ALLOW_IPS` | `*` | Render's load balancer sets `X-Forwarded-For` / `-Proto`; needed for correct client IPs (rate limits, CAPI) and https detection |
| `ENV` | `production` | enables the boot guard, secure cookies and HSTS |
| `OUTBOUND_WEBHOOKS_LIVE`, `LLM_PROVIDER` | `false`, `mock` | safe defaults; turn on when ready |

Free-tier limits to plan around (from <https://render.com/docs/free>, checked 2026-10-13):

- Free web services **spin down after 15 minutes without inbound traffic** and take about a
  minute to wake. Queued jobs are durable in Postgres and resume on the next request; SSE clients
  reconnect automatically.
- **Free Postgres expires 30 days after creation**, then has a 14-day grace period before it is
  deleted with its data. Free databases have no backups and a 1 GB limit. Export regularly and
  upgrade or recreate before expiry:

  ```bash
  pg_dump --no-owner --format=custom "$EXTERNAL_DATABASE_URL" > ofm-$(date +%F).dump
  pg_restore --no-owner --dbname "$NEW_DATABASE_URL" ofm-YYYY-MM-DD.dump
  ```

  (Use the database's *external* connection string from the Render dashboard; the blueprint's
  `ipAllowList: []` blocks external access, so add your IP temporarily for the dump.)
- Free web services have an ephemeral filesystem and no shell or one-off jobs — hence
  Postgres-only state and the bootstrap admin variables.
- 750 free instance hours per workspace per month.

For production on Render, move the web service and database to paid plans, set
`RUN_WORKER_IN_PROCESS=false`, and add a **Background Worker** service with the same image and
environment running the `worker` command.

## Docker image (ghcr.io)

Tagged releases publish `ghcr.io/fernandogarzaaa/omfe` for `linux/amd64` and `linux/arm64`
(tags `X.Y.Z`, `X.Y`, `latest`) with SBOM and provenance attestations.

> GHCR packages pushed from a repository start **private**. To pull without logging in, make the
> package public: GitHub → your profile → **Packages → omfe → Package settings → Change
> visibility → Public**. Otherwise `docker login ghcr.io` with a token that has `read:packages`.

The image: multi-stage build, digest-pinned base images, Python deps installed from hash-pinned
locks, runs as UID `10001`, `HEALTHCHECK` on `/healthz`, data volume `/app/data` (only used by the
SQLite default — use Postgres in production).

```bash
# web (migrates on start; set MIGRATE_ON_START=false to manage migrations yourself)
docker run -d --name ofm-web -p 8000:8000 --env-file prod.env ghcr.io/fernandogarzaaa/omfe:1.0.0

# worker (start after the web container has migrated the schema)
docker run -d --name ofm-worker --env-file prod.env ghcr.io/fernandogarzaaa/omfe:1.0.0 worker

# any CLI command
docker run --rm --env-file prod.env ghcr.io/fernandogarzaaa/omfe:1.0.0 doctor
```

Entrypoint commands: `serve` (default: `ofm migrate` unless `MIGRATE_ON_START=false`, optional
`SEED_DEMO=true` with `SEED_DEMO_ARGS`, then uvicorn on `$PORT` with `$WEB_CONCURRENCY`
workers), `worker`, or any other `ofm` subcommand.

Recommended runtime flags (as in Compose): `--read-only --tmpfs /tmp --cap-drop ALL
--security-opt no-new-privileges:true`.

Put a TLS-terminating proxy or load balancer in front; set `FORWARDED_ALLOW_IPS` to its address.
For more than one web replica, set `REDIS_URL` so rate limits are shared.

## Docker Compose

[`docker-compose.yml`](../docker-compose.yml) runs `postgres` (17-alpine), `app` (seeds the demo
tenant with the known demo passwords) and `worker`, all in mock mode with throwaway dev secrets:

```bash
docker compose up --build                               # http://localhost:8000
docker compose --profile redis --profile n8n up         # + Redis and n8n (:5678)
docker compose run --rm app gen-key                     # generate a master key
docker compose down -v                                  # stop and delete the volumes
```

To use Compose on a server, copy it, set `ENV=production`, replace every secret, remove
`SEED_DEMO`, and put a TLS proxy in front. Pin the n8n image version if you keep that profile.

## Operations

- **Migrations:** `ofm migrate` (runs automatically in `serve`). Back up before upgrading.
- **Health:** `/healthz` (process up), `/readyz` (database reachable), `/metrics` (Prometheus,
  `Authorization: Bearer $METRICS_TOKEN`; 404 when unset).
- **Logs:** JSON to stdout (`LOG_JSON=true`), secrets and PII redacted.
- **Key rotation:** set `MASTER_KEYS=<new>,<old>`, deploy, run `ofm rotate-keys`, then set
  `MASTER_KEYS=<new>`. Rotating `JWT_SECRET` signs everyone out.
- **Check config:** `ofm doctor` after every change — it lists unsafe settings, DB connectivity
  and each tenant's integration modes.
- **Backups:** daily `pg_dump` (or your provider's snapshots) and an occasional restore test.
- **Scaling:** stateless web replicas behind a load balancer + any number of `worker` processes
  (`SKIP LOCKED` prevents double processing); live events fan out via Postgres `LISTEN/NOTIFY`.

# OFM Engine REST contract (v1) — shared by backend and frontend
Base: /api/v1. JSON. Auth: httpOnly cookies `access_token` (15 min JWT) + `refresh_token` (rotating); CSRF: double-submit cookie `csrf_token` echoed in header `X-CSRF-Token` on non-GET. API keys: header `X-API-Key` (automation tools). Errors: {"error":{"code":str,"message":str}}. Lists: ?limit=&cursor= -> {"items":[...],"next_cursor":str|null}. All business data scoped to the caller's tenant.

Auth: POST /auth/login {email,password,totp?} -> {user} | 401 | {"error":{"code":"totp_required"}}; POST /auth/refresh; POST /auth/logout; GET /auth/me -> {id,email,name,role:"admin"|"member",tenant:{id,name},totp_enabled}; POST /auth/totp/setup -> {otpauth_uri}; POST /auth/totp/verify {code}.
Users (admin): GET/POST /users, PATCH/DELETE /users/{id}.
Creators: GET/POST /creators, GET/PATCH/DELETE /creators/{id}. Creator {id,name,handle,status:"active"|"paused"|"onboarding",channels:[str],created_at}.
Recruitment leads: GET /leads?stage=, GET/PATCH /leads/{id}, POST /leads/{id}/rescore. Lead {id,name,email,phone,socials:{},followers:int,earnings_range,timezone,score:int,score_reasons:[str],stage:"new"|"contacted"|"call_booked"|"signed"|"lost",ghl_contact_id,created_at}. Public: POST /public/{tenant_slug}/apply (rate-limited, requires age_confirmed=true & consent=true else 422).
Pipeline: GET /pipeline -> {stages:[{key,label,count,leads:[Lead]}]}.
Tracking links: GET/POST /links, PATCH/DELETE /links/{id}. Link {id,slug,creator_id,channel,destination_url,campaign,clicks:int,created_at}. Public redirect GET /l/{slug} (outside /api).
Revenue: POST /revenue/import (multipart `file` + `mapping` JSON), GET /revenue?creator_id=&from=&to=.
KPIs: GET /kpis?range=7d|30d|90d -> {clicks,leads,signed,subs,revenue_cents,conversion:{click_to_lead,lead_to_signed},by_channel:[{channel,clicks,leads,revenue_cents}],by_creator:[{creator_id,name,revenue_cents,subs}],timeseries:[{date,clicks,leads,revenue_cents}]}.
Live: GET /live/stream (SSE). Events: `event` {type:"click"|"lead"|"capi_sent"|"revenue_import"|"job_failed",payload,at} and `kpi` = **additive delta** {clicks,leads,signed,subs,revenue_cents} covering exactly the `event`s sent just before it (clients add it to their /kpis snapshot).
Automations: GET /automations/webhooks, POST /automations/webhooks {url,events:[str]} -> {id,secret(shown once)}, DELETE /automations/webhooks/{id}; GET /automations/jobs?status=; GET/POST/DELETE /api-keys (key shown once).
AI copy: POST /ai/copy {kind:"recruitment_ad"|"headline"|"followup_sms"|"followup_email"|"social_caption",brief,variants:int<=5} -> {variants:[str],provider,mock:bool} | 422 {"error":{"code":"content_refused"}}.
Integrations (admin): GET /integrations -> [{provider:"ghl"|"meta_capi"|"tiktok"|"llm",configured:bool,mode:"mock"|"live",fields:[{name,set:bool}]}]; PUT /integrations/{provider} {fields:{...}} (write-only, never returned); POST /integrations/{provider}/test -> {ok,mode,detail}.
Audit (admin): GET /audit.
Health: GET /healthz, /readyz, /metrics (token).

## Backend implementation notes (v1.0.0) — additions & clarifications
Everything above is implemented as written. These are additive details/clarifications the frontend can rely on:
- **CSRF**: `csrf_token` cookie (not httpOnly, SameSite=Strict) is issued by login/refresh and seeded on any `/api/*` or HTML response that lacks it. Required (`X-CSRF-Token`) on every non-GET with cookie auth, including `/auth/refresh` and `/auth/logout`. `/auth/login` and `/public/*` are exempt. Missing/wrong -> 403 `csrf_failed`. Requests authenticated by `X-API-Key` never need it.
- **Auth errors** (all 401): `invalid_credentials`, `account_locked` (after LOGIN_MAX_ATTEMPTS=5 failures, LOGIN_LOCKOUT_SECONDS=900), `totp_required`, `invalid_totp`, `refresh_reused` (rotated refresh token replayed -> whole session family revoked), `unauthorized`. `/auth/refresh` and `/auth/login` return `{user}` (same shape as `/auth/me`). `/auth/totp/verify` -> `{ok, totp_enabled}` and re-issues cookies; `/auth/totp/setup` when already enabled -> 409 `totp_already_enabled`; verify before setup -> 400 `totp_not_setup`. Refresh cookie path is `/api/v1/auth`.
- **Me/User shape**: `{id,email,name,role,totp_enabled,is_active,created_at,last_login_at,tenant:{id,name,slug}}` (`tenant` only on /auth/me, login, refresh). `POST /users {email,name?,role?,password?}` -> 201 user (+ `temporary_password` when no password given); 409 `email_taken`; 422 `weak_password`. PATCH `{name?,role?,is_active?,password?}`. Removing/demoting the last admin -> 409 `last_admin`; deleting yourself -> 409 `cannot_delete_self`.
- **RBAC**: admin-only = users, integrations, audit, api-keys, webhook create/delete, DELETE creators/links. Members and API keys can use all other business routes. API keys are rejected (403) on session-only routes (`/auth/me`, `/auth/totp/*`).
- **Extra response fields**: Creator `+bio, avatar_url, bio_links:[{label,url}]` (create/patch accept them; `handle` is lowercased, `[a-z0-9_-]`). Lead `+tier ("hot"|"warm"|"cold"), variant, attribution{}, followers_by_platform{}`; PATCH /leads accepts `{stage?,name?,email?,phone?,timezone?}`; `GET /leads?stage=&tier=`. Link `+capi_on_click, active`; POST `{slug?,creator_id?,channel,destination_url,campaign,capi_on_click?}` (slug auto-generated if omitted; 409 `slug_taken`); PATCH also accepts `active`. `GET /pipeline?per_stage=50`.
- **All list endpoints** (users, creators, leads, links, revenue, webhooks, jobs, api-keys, audit) use the `{items,next_cursor}` envelope. `GET /integrations` returns a bare array as specified.
- **Public apply**: body `{name,email,phone?,socials:{},followers:{platform:int}|int,earnings_range?,timezone?,age_confirmed,consent,variant?,event_id?,attribution:{utm_*,fbc,fbp,ttclid,...}}`. 201 `{ok,id,event_id,duplicate:false,thank_you,booking_url}`; resubmitting the same email -> 200 with `duplicate:true`. Missing 18+/consent -> 422 `age_and_consent_required`. Rate limit 30/min/IP -> 429 `rate_limited`. Unknown tenant -> 404.
- **Revenue import**: multipart `file` (CSV, ≤5 MB, UTF-8) + `mapping` (JSON string; keys `date,creator,campaign,gross,net,new_subs,date_format`; aliases `amount`→`gross`, `subs`→`new_subs` are accepted; unspecified keys fall back to the tenant's defaults; unknown keys -> 422 `invalid_mapping`). -> `{imported,skipped_duplicates,errors:[{row,message}],error_count,revenue_cents,subs}`; 422 `invalid_csv` / `invalid_mapping`. Rows are de-duplicated by content hash. Revenue item: `{id,creator_id,date,campaign,gross_cents,net_cents,revenue_cents,new_subs,source_file,created_at}`. `revenue_cents` everywhere = gross.
- **KPIs**: response also includes `range`. Cached ~30 s per tenant/range, invalidated on clicks, leads, stage changes and imports.
- **Live SSE**: emits `event` (`type` ∈ click|lead|capi_sent|revenue_import|job_failed) with `id:` = sequence number, then one `kpi` event per batch. `kpi` is an **increment** (all five counters always present, zeros included) for exactly the events in that batch, so summing every `kpi` since a snapshot reproduces the snapshot's counters; resuming with `Last-Event-ID` never re-counts events before that id. Per-channel/creator breakdowns are not streamed (the dashboard refetches /kpis every 60 s). Payloads: click `{link_id,slug,channel,device}`, lead `{lead_id,score,tier,variant}` or stage change `{lead_id,stage,from}`, capi_sent `{event_name,event_id,mode}`, revenue_import `{imported,revenue_cents,subs}`, job_failed `{kind,job_id}` (no PII in the feed). Resumable with `Last-Event-ID`; without it the stream starts at the tail. The server closes the stream after `?max_seconds=` (default 300); EventSource reconnects automatically (`retry: 3000`). Keepalive comments every 15 s.
- **Automations**: webhook events `lead.created | lead.stage_changed | link.clicked | revenue.imported | creator.updated | *` (`link.clicked` fires per non-bot click; `creator.updated` on PATCH /creators/{id} with the creator object + `changed:[field]`); URL must be https + public (SSRF guard) else 422 `unsafe_url`. Deliveries are signed `X-OFM-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, "<t>.<body>")>` with `X-OFM-Event`, `X-OFM-Delivery`; receivers should reject |now−t|>300 s and dedupe on delivery id. Real HTTP delivery only when `OUTBOUND_WEBHOOKS_LIVE=true` (mock mode signs + logs). Job item: `{id,kind,status:"queued"|"running"|"retry"|"succeeded"|"dead",attempts,max_attempts,last_error,run_after,created_at,updated_at}`; `GET /automations/jobs?status=&kind=`. **Added**: `POST /automations/jobs/{id}/retry` (dead/retry jobs only, else 409). API key item `{id,name,prefix,role,created_at,last_used_at,revoked}`; POST returns it plus `key` once.
- **AI copy**: refusals (explicit, minors, impersonation/fake personas) -> 422 `content_refused` with a reason message, also audited.
- **Integrations**: field items also carry `required` and `secret` booleans. Fields: ghl `token, location_id, pipeline_id?, workflow_id?, workflow_webhook_url?`; meta_capi `access_token, pixel_id, test_event_code?`; tiktok `access_token, pixel_code, test_event_code?`; llm `anthropic_api_key?, openai_api_key?`. PUT with `""`/null clears a field; unknown field -> 422. PUT returns the provider's status object. Secrets are envelope-encrypted; IDs are stored as tenant overrides; nothing is ever echoed.
- **Added**: `POST /api/v1/hooks/inbound/{tenant_slug}` — signed callbacks from n8n/Make/Zapier (same signature scheme, tenant secret `INBOUND_HMAC_SECRET`), 5-min window, each signature accepted once (409 `replayed`). Body `{"type":"lead.stage","lead_id","stage"}`.
- **Health**: `/healthz`, `/readyz`, `/metrics` are served at the root and under `/api/v1`. `/metrics` requires `Authorization: Bearer $METRICS_TOKEN` (env read on every request); 404 when no token is configured.
- **Pages (outside /api)**: `GET /apply/{tenant_slug}` (A/B variant via sticky cookie, `?v=` override), `POST /apply/{tenant_slug}` (no-JS form fallback), `GET /c/{tenant}/{creator_handle}`, `GET /l/{slug}` (302, or a Pixel interstitial sharing `event_id` when the link has `capi_on_click`; `X-OFM-Event-Id` header). Any other non-API GET serves the SPA (`src/ofm_engine/web/dist/index.html`).

## Integration reconciliation (v1.0.0 — final)
Verified end-to-end against the real backend serving the built SPA (`scripts/e2e_ui.sh`, 47 checks) and pinned by
`tests/test_integration_contract.py` + `frontend/src/lib/__tests__`. Every former "assumed" type in
`frontend/src/lib/types.ts` now mirrors `src/ofm_engine/api/serializers.py`:
- **SSE `kpi`**: increments (backend `_kpi_delta`, frontend `applyKpiDelta`). Chosen over snapshot-replace because the
  dashboard holds three ranges (7d/30d/90d) and a single delta applies to all of them; tested on both sides.
- **`totp_required`**: 401 `{"error":{"code":"totp_required"}}` from /auth/login → UI switches to the code step; `invalid_totp` on a wrong code.
- **/auth/refresh** → `{user}` (same as login). The SPA only needs `ok`; `api.auth.refreshUser()` exposes the body.
- **GET /revenue** items: `{id,creator_id,date,campaign,gross_cents,net_cents,revenue_cents,new_subs,source_file,created_at}`.
- **Import result**: `{imported,skipped_duplicates,errors:[{row,message}],error_count,revenue_cents,subs}`; UI sends `{date,creator,gross,new_subs?,net?,campaign?}`.
- **Jobs**: statuses `queued|running|retry|succeeded|dead`; UI shows a Retry button (POST /automations/jobs/{id}/retry) for `dead`/`retry`.
- **Webhooks list**: `{items:[{id,url,events,active,created_at}],next_cursor}`; create returns that object + `secret` (once).
- **API keys**: list `{id,name,prefix,role,created_at,last_used_at,revoked}` (revoked keys are omitted); POST adds `key` once; DELETE /api-keys/{id} → `{ok:true}`.
- **Audit**: `{id,actor_id,actor_type,actor,action,target,meta,created_at}`; `actor` is resolved server-side (user email / `api key: <name>` / actor_type). IPs are stored only as keyed hashes and never returned.
- **POST /users**: 201 user + `temporary_password` when no password was given (UI shows it once).
- **Lists**: every list endpoint returns `{items,next_cursor}`; only GET /integrations is a bare array.
- **Demo logins**: `admin@demo.agency` / `member@demo.agency`, password `demo-pass-2026` in both the in-browser mock
  (`VITE_MOCK=1`) and `ofm seed-demo --known-passwords` (refused when `ENV=production`; without the flag passwords are random).
  The mock-only `owner@demo.agency` demonstrates 2FA with code `123456`.
